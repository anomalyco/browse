# Browse evals

Use the Bun version in `package.json` and Node 24. Results are written as one JSON record and log per check under `evals/results/<run>/`. CI uploads that directory even on failure.

1. **PR tier (Linux/macOS):** install dependencies with `bun install --frozen-lockfile` at the root and in `cli/`. Install ShellCheck and Chromium (`cd cli && node node_modules/patchright-core/cli.js install --no-shell chromium`; use `--with-deps` on Linux). Run `bun evals/run.ts pr` at the root. This typechecks, lints, builds, runs the extension/CLI suites, checks the release package, compiles and packs the host binary, and runs all three headless browser harnesses. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` can point to an existing Chrome for Testing.
2. **Built artifact tier:** after the PR tier, run `bun evals/run.ts artifact`. Alternatively provide the zip and npm tarball in `EVAL_BUILD_DIR`, platform tarballs in `EVAL_BINARIES_DIR`, and the exact `EVAL_BUILD_VERSION`. CI downloads immutable uploads onto fresh Linux, macOS arm64 and Windows runners with no build dependencies. For local runs use an idle checkout: the binary check temporarily renames and restores its two `node_modules` directories.
3. **Published artifact tier:** `bun evals/run.ts artifact --version 0.0.7` (or an exact dev version). This fetches npm's tarballs and runs the installer against npm. The extension isn't on npm: stable zips come from the GitHub release; dev zips from the immutable release-service URL in the CLI. Immediately after publishing, CI uses the same run's zip because the GitHub release doesn't exist yet.

The artifact tier checks `--version`, relay `/version`, and an MCP stdio `initialize` + nonempty `tools/list` for the unpacked executable and a fresh, lockfile-free npm install. It runs the actual Bash/PowerShell installer with `--no-setup`, checks its installed binary and relay, and validates the extension zip against the release permission allowlist. `BROWSE_INSTALL_BASE_URL=http://127.0.0.1:PORT` is **only for testing** the installer against built tarballs; unset, downloads use the HTTPS npm registry. No browser or running relay is needed.

**Gates:** all PR checks block. Changes to CLI, installers, package files, release/build scripts, workflows or evals also run the three artifact checks; pushes to `dev` always do. All release modes require all three platforms **before** publish. Actual npm publishes are verified again on every OS (registry propagation is retried, test failures aren't). A failing stable verification blocks the store and GitHub release and triggers npm tag recovery; see [RELEASING.md](../RELEASING.md#undoing-a-bad-release).
